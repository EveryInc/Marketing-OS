# Marketing OS Concepts

## Compound Marketing

### Compound Marketing
The operating method in which every project produces effective marketing now and
improves the system that produces the next project. Its governed loop is context,
strategy, market, and memory.

### Decision record
The canonical ledger in a run's `run.json` for approved strategy, source authority,
protected language, open questions, and rejected directions. Markdown is a generated
human projection. Downstream work inherits the ledger's digest and stable IDs instead of
reconstructing strategy from source material.

### Governed run
A project-local, single-writer record with one lifecycle, one routed output, one artifact,
and explicit human gates. Closed and abandoned runs are terminal; related work uses a
linked successor.

### Handoff contract
The machine-readable sidecar that gives a specialist the exact run, decision-record
digest, governed IDs, unresolved questions, artifact owner, and record paths it must
preserve.

### Artifact receipt
A machine-readable record connecting an accepted artifact to its run, decision-record
digest, preserved decision IDs, content revision or hash, and named human verifier. The
checker validates consistency; it does not authenticate the verifier.

### Readiness
The monotonic evidence states returned by the checker: structural readiness for coherent
governance, operational readiness for a content-bound accepted run, and comparison
readiness for a predeclared follow-up. A single run is never proof-ready.

### Compounding proof
Evidence that a comparable second real run inherited prior decisions and required less
human correction without losing quality. Structural checks and retrospective cases are
useful baselines, but do not establish this claim.

## Art-direction production

### Locked content manifest
The complete approved set of strings, omissions, placeholders, annotations, ordering, and
source provenance that a visual artifact may arrange but may not silently rewrite or
expand.

### Canonical source surface
The exact editable file, page, frame or node, component state, dimensions, and revision
that owns the structure from which a visual production branch begins.

### Reference grammar
The operational translation of a visual reference into invariants that must survive,
variables that may change, and literal shortcuts that are forbidden.

### Controlled branch
A visual iteration that starts from a named parent, holds its approved inputs and
invariants fixed, and changes one declared variable so the result can teach the system
something specific.
