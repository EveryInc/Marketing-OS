# Performance Copywriting

Use this skill when a short line must earn a click and a conversion from a cold or warm
reader: paid search, paid social, chat-surface ads, sponsored placements, and the landing
copy those ads lead to. It turns a verified offer into lines that can be tested, and it
keeps the team honest about what a test at a given budget can and cannot show.

The core finding from the research: wording features barely predict which line wins, and
small tests mostly measure noise. So the offer, the promise-to-page match, and clarity carry
the result. Test different angles before different words.

## When to invoke

- Writing headline and description pairs for any paid ad unit
- Reviewing ad copy before upload or before a creative test
- Writing the landing, signup-wall, or welcome copy an ad points to
- Planning which lines to test and how much traffic the test needs
- Turning campaign results into reusable rules

## The loop

1. **Name the action and the offer.** One action per ad. If the offer is weak, fix the
   offer; copy cannot rescue it (`craft/copywriting-halbert`).
2. **Place the reader.** State their awareness level and where they are when the ad
   appears (`references/line-checks.md`).
3. **Write the plain claim.** One sentence a stranger would understand, with the concrete
   thing the reader gets. Every line derives from it (C5, C8).
4. **Draft by angle.** Write two to four lines that each take a different angle: situation,
   outcome, objection, self-check, task. Do not draft wording variants of one angle yet.
5. **Run the line checks.** Every line passes `references/line-checks.md` or is cut.
6. **Echo the promise.** The landing headline repeats the winning promise in the reader's
   words. Check C6 against the page the ad actually opens.
7. **Size the test.** Use `references/test-reality.md` to decide whether the budget can
   read a difference. If not, say so in the plan and treat results as directional.
8. **Fit the channel.** Apply the channel file in `references/channels/` for limits,
   targeting, and review rules.
9. **Record and promote.** Log each line, angle, and outcome in the private project source.
   Promote a pattern to this skill only through the Marketing OS promotion rule
   (`foundation/marketing-os/references/knowledge-boundaries.md`).

## Evidence standard

Every rule here carries a grade from `references/evidence-ledger.md`: strong, moderate,
weak, or practitioner. State the grade when a rule decides a choice. Never call untested
copy high-converting. Never present a vendor benchmark or a single case study as a law.

## Quick checklist

- [ ] One action, one offer, one plain claim per ad
- [ ] Reader's awareness level and moment named
- [ ] Lines differ by angle, not just wording
- [ ] Every line passes the line checks, including promise matches page
- [ ] Landing headline echoes the ad's promise
- [ ] Test sized to traffic; underpowered tests labeled directional
- [ ] Channel limits and review rules applied
- [ ] Results logged privately; promotion rule applied before changing this skill
