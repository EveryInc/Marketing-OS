# Line Checks

Run every ad line through these checks before upload. A line that fails is cut or rewritten.
Grades refer to `evidence-ledger.md`.

## Before writing

- **Action:** What single action should the reader take? One per ad.
- **Offer:** Is there something worth clicking for? A free resource, trial, or answer the
  reader wants now. If not, fix the offer.
- **Awareness:** Where is the reader? Unaware, problem-aware, solution-aware,
  product-aware, or most-aware (practitioner). Write the angle that fits.
- **Moment:** Where does the ad appear and what was the reader just doing? Write for that
  moment, not a generic feed.

## Each line

1. **Plain claim first.** Can a stranger restate the offer after one read? (practitioner)
2. **One job.** The headline does one thing; the description adds one new fact, not a
   repeat (C10).
3. **Concrete detail.** Names a task, number, or thing the reader gets. Vague outcomes like
   "what's next" or "level up" need a concrete description beside them.
4. **Promise matches page.** What the line promises is exactly what the landing page
   delivers, on the plan or product the reader actually has (C6).
5. **Real objection.** If one thing stops the click (cost, skill, time), answer it with a
   true statement, such as "free" or "no coding needed."
6. **Reader's frame.** Prefer "you," "I/my," or a person over the brand's "we" (moderate).
7. **Read aloud.** No stumbles, no jargon the reader wouldn't use (C8).
8. **Competitor test.** Could a competitor run this line unchanged? If yes, add what only
   this offer has.
9. **Honest urgency.** No invented deadlines, scarcity, or savings (Halbert).
10. **Fits the unit.** Within the channel's hard limits; check how it truncates on a phone.

## Across a set

- Each ad in a test takes a different angle.
- No two descriptions in one group carry the same proof.
- The landing headline echoes the promise of the ads that send traffic to it.
