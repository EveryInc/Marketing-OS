# Task context and clean handoffs

Use for substantive work, a changed brief, or a reset. Small edits need only the current
artifact, requested change, and protected constraints. Reuse an existing brief or decision
record; do not create a competing intake document.

## Assemble the working brief

Recover from supplied material and current authoritative sources:

- Deliverable, audience, intended outcome, and definition of done.
- Approved decisions and exact protected words or visual choices.
- Source links or paths, relevant version/date, and what each source owns.
- Missing facts, unresolved decisions, and the next authorized action.

Keep this in working notes or the existing project record. Ask only about consequential
gaps the sources cannot settle. Do not ask the user to repeat available context. A draft,
prior assistant answer, or handoff summary is not approval or independent evidence.
Resolve authority before recency: a newer suggestion does not replace an approved decision.
If authorized sources conflict, name the conflict and obtain the missing decision.

## Load by decision

Read the selected skill and the resources its applicable route requires. Dependency lists
are not instructions to preload every specialist. Do not skip approval, source verification,
accessibility, confidentiality, or production requirements to save context.

| Work | Context to bring forward |
|---|---|
| New strategic choice, positioning, identity, or campaign premise | Method and collaboration; relevant brand, audience, evidence, and theory references |
| Execution of approved strategy | Current approved brief; relevant brand/channel/production rules; source evidence needed for claims |
| Narrow revision | Current artifact, requested delta, protected content, and the rule needed to make and check the change |
| Learning or benchmarking | Comparable before/after evidence, applicable learning rules, evaluation and measurement limits |

Keep the full strategy and theoretical library available. Retrieve additional relevant
references when a decision needs them; do not replace the library with a thin summary.
For examples, state the dimension they govern (structure, voice, crop, proof, etc.). Do
not inherit incidental wording, colors, dates, or offers. Mark old project facts historical
and verify them before reuse. Read each selected instruction resource completely.

## Continue or reset

Continue ordinary corrections in the current chat. Recommend a fresh chat when the task
or governing direction changes substantially, a corrected assumption recurs, or revisions
keep reproducing a rejected approach. Repair the working brief before drafting again.
Do not make reset a mandatory response to every error or a fixed message-count limit.

Prepare a handoff when useful, but create or message another chat only with explicit user
authorization. Do not change memory settings or start a scheduled task. Loading this file
does not remove earlier context from the current conversation.

## Handoff only the current state

Use the existing project record, or a short project-local note outside the public skills
repository. Include the task and done condition, current artifact/version, approved
decisions with evidence references, protected content, unresolved questions, verification
status, and next authorized action. Preserve the full source links and current repository
branch/commit/dirty-state facts when relevant. Do not imply that pending work shipped.

Check the note against authoritative sources before calling it verified. If a source is
unavailable, mark the affected statement unverified. Exclude abandoned drafts and old
assumptions from active instructions; retain a short supersession warning only when it
prevents a likely recurrence. Preserve the underlying audit history separately.

In the next chat, read the handoff and necessary sources; recheck volatile facts. A
summary never expands authorization to send, publish, spend, or edit another surface.

## Compound by replacement

Before adding guidance, identify the future decision it changes and check for an existing
rule. Prefer clarifying or replacing overlapping guidance. Remove superseded instructions
only after checking their callers and preserving still-valid constraints. Keep one-off
choices and temporary facts with the project. Use the existing learning/promotion gate;
neither this protocol nor a memorable article proves better results.

For a prospective trial, record avoidable correction rounds caused by stale, missing, or
conflicting context. Guardrails: protected-detail survival, unsupported claims, and human
quality review. Compare similar assignments; without a baseline, record one and leave
improvement unproven. Synthetic tests establish behavior only, not live performance.
