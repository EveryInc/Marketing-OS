# Beta Activation

Use the smallest metric hierarchy that can decide which audience, workflow, message, or
launch path deserves more investment.

## Metric hierarchy

1. **Primary activation metric:** A qualified workspace completes the mechanism-proving
   second run within a defined window.
2. **Behavioral diagnostics:** Time to first useful artifact, time to second run, repeat
   use, workflow completion, correction acceptance, and measurable improvement across
   runs.
3. **Commercial diagnostics:** Willingness to pay, pricing objections, conversion, and
   retention intent.
4. **Launch proof:** Publishable external receipts, credible non-company case-study
   candidates, and measurable improvement in the promised workflow.
5. **Cohort decision:** Compare activation, repeat use, willingness to pay, and
   publishable proof across separately tested audiences.
6. **Guardrails:** Trust, control, security, setup burden, failure severity, and support
   load.

## Preflight

Before beta:

- Define a qualified workspace.
- Define the first and second run.
- Choose the activation window.
- Instrument run completion, correction behavior, and repeat use.
- Record the data source, owner, reporting cadence, and decision date.
- Capture customer descriptions before exposing them to official positioning.

Set targets from evidence. If no baseline exists, define the metric and decision first,
then set the threshold after an initial sample. Never invent a success threshold to make
the plan look complete.

## Evidence discipline

Always report:

- Denominator and sample size.
- Selection and survivorship bias.
- Attribution limits.
- Whether evidence measures individual productivity, team behavior, or company outcomes.
- Whether the result supports causality, correlation, or only directional learning.

End the beta readout with a choice: lead cohort, revise the test, expand the sample, or
stop.
